BUILD: "Fetch" — a full-featured Windows download manager cloning the complete
functional surface of Internet Download Manager (IDM), version 1.0, shipping
as a signed MSI installer.

This prompt is the whole job: architecture, every module, every file, every
requirement, and the acceptance criteria. No stubs. No TODOs. No "left as an
exercise." Every module compiles and runs. Every feature listed is implemented
or explicitly marked optional at the end.

0. CONSTRAINTS
═══════════════════════════════════════════════════════════════════
- Target: Windows 10 22H2 and Windows 11, x64. Also builds for arm64.
- Engine language: C++20. Compiler: MSVC 19.38+ (Visual Studio 2022 17.8+).
- UI language: C# 12 on .NET 8, WPF. MVVM, no code-behind logic.
- Build system: CMake 3.28+ generating Visual Studio 2022 solution.
- Package: WiX v4 producing fetch.msi, per-user install (no admin prompt).
- TLS verification ON by default. Override only with a visible warning.
- No credential harvesting. No cookie exfiltration. No adware. No browser hijack.
- No use of Internet Download Manager's name, logo, icons, or brand assets.
  The product is called Fetch. It is not affiliated with Tonec Inc.
- AMSI-scan every completed file via IAttachmentExecute before final rename.
- Sanitize every server-provided filename. Reject path traversal, reserved
  device names (CON, PRN, AUX, NUL, COM1-9, LPT1-9), and control chars.

4. ENGINE REQUIREMENTS (fetchd)
═══════════════════════════════════════════════════════════════════

4.1 PRE-FLIGHT (per job, before segmentation)
- Send HEAD with configured UA, Referer, Cookies, custom headers, auth.
- Read: Content-Length, Accept-Ranges, ETag, Last-Modified,
  Content-Disposition, Content-Type, Content-Encoding.
- Follow redirects up to 10 hops. Record final_url.
- If Accept-Ranges: bytes and Content-Length >= min_segment_bytes * 2,
  segment; otherwise single stream.
- Chunked (no Content-Length): single stream, indeterminate progress.
- If server returns Content-Encoding: gzip/br on a ranged resource,
  disable segmentation (ranges on encoded bodies are meaningless).

4.2 SEGMENTER
- Default segments: 8. Configurable 1..32.
- min_segment_bytes default 1 MiB; refuse to create a segment below this.
- Each segment: Range: bytes=start-end inclusive.
- Dynamic re-split: every 2s, if a running segment's rate is < 50% of the
  fastest running segment and its remaining bytes >= 2*min_segment_bytes,
  split its remaining range into two and hand the new tail to the pool.
- Merge adjacent done segments into a single "done" span for the writer.
- All math on int64_t. Byte offsets are absolute in the decoded file.

4.3 CONNECTION POOL
- Global cap (default 32), per-host cap (default 8), per-job cap (default 8).
- Retries: 5 max, exponential backoff starting at 1s (1,2,4,8,16).
- On drop mid-segment: reconnect, re-issue Range from last written+1,
  verify ETag unchanged; if changed, restart the whole job.
- Keep-alive on where the server advertises it.
- All socket work on a dedicated thread pool; engine never blocks the
  IPC thread.

4.4 WRITER
- Each segment writes to <file>.part.<N> in the temp dir.
- On segment done: mark it closed; do not delete.
- Finalizer: when all segments are done, concatenate in index order into
  <file>.part, then fsync, then atomic MoveFileEx with MOVEFILE_REPLACE_EXISTING
  to the final name.
- On any error: leave .part and .part.N files on disk for resume.
- Filenames sanitized: strip control chars, reject reserved names, cap to
  255 chars, preserve extension, use Windows-safe chars only.

4.5 VERIFIER
- Optional MD5, SHA-1, or SHA-256.
- Source of expected hash: server header (Digest, ETag-if-strong, or
  Content-MD5), or user-supplied.
- On mismatch: job status = failed, error = "hash mismatch", keep parts.
- On match: proceed to final rename.

4.6 PAUSE / RESUME
- Every state change (status, per-segment written offset) is persisted to
  SQLite before the state is considered committed.
- Resume across app restart: on startup, any job in running state is
  re-classified as paused, then resumed on demand.
- Resume re-validates ETag via HEAD. Changed -> restart job. Same -> resume.
- Resume across reboot is the same path as across restart.

4.7 THROTTLE
- Token bucket per job and global.
- Limit in KB/s, 0 = unlimited.
- Optional schedule: e.g. global limit 0 kbps 00:00-08:00, 512 kbps
  08:00-24:00. Represented as JSON in settings.scheduler_windows.

4.8 QUEUE / SCHEDULER
- Max concurrent jobs: default 3, configurable 1..16.
- Priority: higher first, FIFO within same priority.
- Category rules auto-assign category by extension and/or host.
- Time-window scheduler: a job can be scheduled to start and/or stop at
  wall-clock windows; the scheduler wakes every 15s and acts.
- Pause/resume/stop/remove via IPC, always consistent with persisted state.

4.9 ENGINE ORCHESTRATION
- One Engine instance owns: pool, scheduler, throttle, DB handle, event bus.
- Engine::add_job(url, opts) -> job_id, persists, enqueues, returns.
- Engine::pause/resume/stop/remove(job_id) are idempotent.
- Engine::list_jobs()/get_job(id) return model structs.
- Progress events emitted at most 4 Hz per job.
- All errors are values, not exceptions, across module boundaries.

5. NETWORK LAYER
═══════════════════════════════════════════════════════════════════
- HTTP/1.1 and HTTP/2 via WinHTTP. HTTPS via SChannel with system trust.
- Optional SPKI pin per host, configured in settings.
- FTP and FTPS via WinINet with explicit TLS.
- Optional BitTorrent via libtorrent-rasterbar (OFF by default; build flag).
- Optional Metalink parsing (OFF by default; build flag).
- Proxy: system (WinHTTP default), manual URL, PAC URL, SOCKS5.
- Auth: Basic, Digest, NTLM, Bearer; per-job credentials override global.
- Cookies: per-job jar; import from Chrome/Edge/Firefox profiles by path;
  never transmit cookies to hosts other than the job's host.
- Custom headers per job: User-Agent, Referer, Cookie, Accept-Language,
  and arbitrary key/value pairs.

6. STORE (SQLite)
═══════════════════════════════════════════════════════════════════

- Migrations: forward-only, numbered, recorded in a meta table.

- jobs_repo: insert_job, update_status, update_progress, update_etag,

- settings_repo: get_setting, set_setting, get_all_settings,

═══════════════════════════════════════════════════════════════════
7. IPC (UI and CLI and NM host <-> engine)
═══════════════════════════════════════════════════════════════════
- Pipe name \\.\pipe\fetchd. Multi-client. One thread per client.
- Framing: newline-delimited UTF-8 JSON, one message per line.
- Request: {"id":uint,"cmd":string,"args":object}
- Response: {"id":uint,"ok":bool,"data":object,"error":string|null}
- Event (pushed, no id): {"event":string,"data":object}
- Commands: add_job, pause, resume, stop, remove, list_jobs, get_job,
  get_settings, set_settings, subscribe_events.
- Events: job_added, job_progress, job_done, job_failed.
- Clients reconnect automatically on pipe drop with backoff (100ms..2s).
- Server tolerates partial lines and oversized messages (cap 1 MiB/line).

15. SECURITY AND HONESTY (build-time constraints, not moral notes)
═══════════════════════════════════════════════════════════════════
- TLS verification always on unless the user explicitly toggles a visible
  warning and confirms per-host.

  telemetry.

  search provider.

  the job is marked failed and the file is left in the temp dir with a
  clear name so the user can inspect or delete.
- Filenames sanitized; path traversal rejected; reserved names rejected.
- Subprocess launches use CreateProcessW with an explicit argv, never
  a shell string.
